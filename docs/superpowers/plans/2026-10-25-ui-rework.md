# camlab UI rework Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Portrait-first viewfinder shell with drawers, a plain-language HUD, tooltips and key map, server-side AI Auto on the Claude API, and a brand-authentic app icon, in both the web build and the Mac app.

**Architecture:** The UI stays one file (`ui/index.html`, vanilla JS/CSS) served by `server/api.py`; layout mode is driven by the live frame's aspect, drawers persist in `localStorage`. The server grows one module, `server/autopilot.py`, a manual Claude tool-use loop that calls the existing `Controller` methods (all guardrails stay in the controller), plus context persistence in `server/state.py`/`controller.py` and a light HUD analysis in the live loop. Icon assets live in `assets/icon/` and are wired into `app/camlab.spec`.

**Tech Stack:** Python 3.14, FastAPI/uvicorn, `anthropic` SDK (Python, new dependency), Pillow/numpy, pytest; vanilla HTML/CSS/JS; PyInstaller + `iconutil`.

**Spec:** `docs/superpowers/specs/2026-10-25-ui-rework-design.md`

## Global Constraints

- Not a git repo: **commit nothing**; "commit" steps are omitted.
- EDSDK only on the process main thread; nothing in this plan touches the camera backends.
- Never delete from the card; the autopilot exposes no record/pull/delete/save tools.
- Hardware runs happen from the desktop terminal panel only; shell runs use `--camera mock` with a scratch `CAMLAB_HOME` whose lights are `manual`.
- Model id `claude-opus-5-5`; omit `thinking` (adaptive by default); `output_config.effort` from config, default `medium`; never send `budget_tokens`, `temperature`, or forced `tool_choice`.
- Gold is the only accent colour; flat hairline styling; Bodoni Moda small caps for the CTC wordmark.
- Tests: `.venv/bin/python -m pytest tests -q` must stay green (89 before this work).

## Review Focus

1. Frame aspect flips mid-session (Orient toggled, body turned): layout must switch modes without a reload and the ROI/guides overlay must redraw in place. Test: Task 2 `test_set_context_broadcasts_camera` (server side) plus the manual browser check in Task 9.
2. Live view with no capture yet: HUD must show exposure chips from the histogram alone and say "no capture yet" for focus/face, not throw. Test: Task 4 `test_live_hud_payload`.
3. AI Auto pressed while recording, or REC pressed mid-run: the run must refuse/stop and the camera must never be left mid-change. Test: Task 6 `test_autopilot_refuses_while_recording`, `test_record_start_stops_autopilot`.
4. API returns `stop_reason: refusal` or raises: the run ends with a readable log line and status `error`, cost still reported. Test: Task 6 `test_autopilot_api_error_ends_run`.
5. `localStorage` unavailable (private window, WKWebView quirk): drawers must still work with defaults. Covered in Task 1 by wrapping storage in try/catch; manual check in Task 9.
